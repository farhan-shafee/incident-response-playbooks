# Security Policy

## Scope

This repository contains synthetic incident-response portfolio documentation and templates. It is not a production incident response service, and no live investigation or containment operations are supported here.

## Reporting

**Do not put credentials, access tokens, private logs, customer data, or an unpatched sensitive vulnerability into a public GitHub issue, pull request, discussion, or comment.**

- On this repository's GitHub **Security** tab, use **Report a vulnerability** only **if enabled and visibly available**. Do not assume private vulnerability reporting is configured or that opening an ordinary issue is private.
- If no verified private reporting channel is available, do not publish the sensitive details. Seek a verified private maintainer contact route before submitting them; this file does not claim a particular private channel or response SLA exists.
- For sanitized, non-sensitive documentation corrections, a regular public GitHub issue or pull request is appropriate. Do not use public reports to disclose secrets or sensitive evidence.

If a credential may have been exposed, notify its responsible owner through an authorized private channel so it can be assessed and revoked or rotated. Removing a value from Git history does **not** revoke it.

## Sensitive Data Handling

Only fabricated or explicitly safe public example data belongs in this repository. Do not submit real credentials, customer data, internal logs, confidential artifacts, or malicious executables, even if identifiers have been replaced. Avoid including personal information in incident examples.
